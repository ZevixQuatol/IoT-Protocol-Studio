# 协议解析核心

> 更新日期：2026-08-28  
> 适用范围：Portable C++ Core

## 1. 目标

协议解析入口负责组合现有 HEX、Schema 和固定布局 Codec，使调用方不再自行查找 `MessageDefinition`、转换 HEX 或传递协议默认字节序。

```text
ProtocolSchema + Message 名称 + HEX / ByteBuffer
  → 查找 MessageDefinition
  → HEX 转 ByteBuffer（HEX 输入时）
  → FixedLayoutCodec Decode
  → DecodedMessage + FieldRange
```

反向链路为：

```text
ProtocolSchema + StructuredMessage
  → 按 message_name 查找 MessageDefinition
  → FixedLayoutCodec Encode
  → ByteBuffer / 规范化 HEX
```

## 2. 公共 API

公共入口位于 `iotps/core/codec/codec.hpp`：

```cpp
decode_protocol_message(protocol, message_name, bytes);
decode_protocol_hex(protocol, message_name, hex);
encode_protocol_message(protocol, message);
encode_protocol_hex(protocol, message);
```

所有入口复用 `ProtocolSchema::protocol.default_byte_order`，Field 级 `endian` 仍由 `FixedLayoutCodec` 覆盖。

## 3. 错误契约

协议入口使用稳定的 `ProtocolCodecErrorCode`：

| 错误码 | 含义 |
|---|---|
| `message_not_found` | Schema 中不存在指定 Message |
| `hex_parse_failed` | HEX 文本无法转换为 ByteBuffer |
| `decode_failed` | 下层固定布局 Decode 失败 |
| `encode_failed` | 下层固定布局 Encode 失败 |

下层 HEX/Codec 错误码保留在 `detail` 中，字段路径、字节偏移和源码位置继续向上传递。

## 4. 当前边界

当前调用方必须明确传入 Message 名称。`typeId` 只是 Message 元数据，Schema 尚未定义它对应哪个 wire 字段，因此不能据此自动识别报文类型。

本入口已覆盖固定 Primitive、固定 UTF-8 string/bytes、固定 Primitive Array、固定 `length`/`offset`、大小端和最小 `lengthOf`。自动 Message 匹配、动态 Array、Struct、Condition、BCD、timestamp、Enum、BitField 和 Checksum 组合仍属于后续 Schema/Codec 阶段。
