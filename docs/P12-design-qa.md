## 修正与复查

1. 详情区的 16 字节 HEX 行挤压 ASCII。改为每行 8 字节，复查 18 字节报文的 HEX / ASCII 均完整可见。
2. 全局按钮 hover 覆盖主要操作底色。提高 P12 主要操作 hover 选择器优先级，重新检查导入及播放按钮。
3. 回放表继承历史表的列宽后 HEX 仅显示少量字符。独立设置回放 HEX 列使用剩余宽度，长度列显示字节数；最终截图可读取较长 HEX 摘要。
4. 回放当前位置离开可视区域。选中记录随进度滚动，跳到第 80 条后表格 scrollTop 为 1809，当前行可见且详情同步。
5. 浅色只读标识、失败 / 警告文字对比度不足。增加浅色语义色，最终只读标识为 `rgb(23, 97, 128)`。
6. 日期输入在调用 stop 引发重渲染时被重置。事件值先保存到局部变量，再停止及更新范围；有效范围 / 反向范围均检查。
7. 停止后旧等待器仍可能更新一次时间。等待后再次检查取消代数，阻止旧任务更新进度。
8. 成功更换文件后清除旧搜索、方向、解析、消息 / 时间和客户端过滤，防止新文件被旧条件隐藏。

最终没有未解决的 P0 / P1 / P2 视觉或交互问题。保留产品原有标题栏、品牌、导航及图标；精确到毫秒的独立日期输入在紧凑窗口允许换行，详情在低高度窗口内部滚动。这些与压缩设计板的密度差异属于 P3 后续微调。

## 交互验证

- 历史 fixture 含 80 条真实格式记录（40 条 RAW 与 40 条 FRAME）。RX + StatusReply 组合筛选得到 20 条；字段选择高亮对应 4 个 HEX 字节。
- PCAP fixture：43 个数据包、82 条保留记录、39 帧解析成功、1 帧解析失败、3 项诊断。分类为未支持 2 次、截断 1 次；诊断筛选显示 2 条 SYS 记录。诊断次数可来自同一包，界面没有将其当作互斥数据包总数。
- 16× 离线播放及范围内循环的发送调用为 0。
- 实际发送模式未明确选择目标时禁用；选择目标后 RAW TX 发送 20 条，完整 RX 帧额外发送 20 条，未重复发送 RAW 与 FRAME 副本。
- 暂停后进度保持；速度调整、停止、重新开始和进度跳转可用。
- 14:35:22 至 14:35:23 的范围得到 12 条记录。结束早于开始时禁止播放；进度跳到范围末尾选择第 22 条。
- 无效 PCAP magic 保留原有 80 条历史记录；损坏历史 JSON 保留原有 82 条 PCAP 记录。
- 1280 / 960 宽度下没有 document 水平溢出。窄窗口的详情移至下方，表格内部可滚动。
- 最终新加载的浏览器 error / warning 日志为空。
