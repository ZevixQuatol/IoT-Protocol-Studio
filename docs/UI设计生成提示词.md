# IoT Protocol Studio UI 设计生成提示词

日期：2026-10-01。用途：依据用户提供的深色交通管理界面参考图，为当前 Windows 桌面 GUI 生成统一的首版 UI 方案。本文是设计生成输入，未修改应用界面。

## 使用顺序

1. 将参考图与下面的“总提示词”一起交给设计生成工具。
2. 先生成设计规范、组件板、协议结构与通信工作台两张关键页面，确认方向后沿用同一套规范生成其余页面。
3. 支持多页面的工具按页面清单创建独立画板；单张图工具逐次使用文末的“逐页生成模板”。

配色和尺寸是适配本产品的设计建议，不是对照片的精确取样。以代码中当前可用入口及开发阶段 0–6 为功能范围；旧清单中的未同步状态不作为新增功能依据。

## 总提示词（可整体复制）

```text
你是一位专注桌面开发工具与工业通信软件的产品设计师。请为 IoT Protocol Studio 设计一套完整、一致、可实现的高保真桌面 UI。随附参考图决定视觉方向，下面的功能说明决定产品内容与交互范围。

【一、产品与设计目标】
产品名称：IoT Protocol Studio，当前版本 0.1.0。
平台：Windows x64 桌面应用。
主要用户：协议开发、嵌入式开发、设备联调和测试工程师。
主要流程：打开项目 → 定义协议 → 编辑消息字段 → 生成报文 → 建立通信 → 收发与解析 → 定位字段和异常 → 保存记录 → 离线分析与回放。
默认界面语言为简体中文，协议名、字段名、HEX、地址、数值保留技术表达。中文与英文分别切换，避免所有标签同时双语造成拥挤。
设计目标：具有参考图的深色工业质感，同时能支撑长时间阅读代码、HEX、表格和通信日志。

【二、从参考图继承的视觉特征】
继承：近黑与石墨灰的背景、带少量灰绿倾向的低饱和配色、柔和圆角、细而克制的边界、半透明面板层次、胶囊状选中态、少量绿色状态点、纤细线条图标、平静的排版与局部浮动详情面板。
将参考图中的大面积主工作区转化为协议编辑、HEX 分析或记录时间线；左侧小面板转化为项目目录、连接参数和上下文信息。
完整展示正视角的应用界面，适用于工程实现。画面中不出现手持设备、平板外框、透视倾斜、摄影场景、交通地图或车辆内容。
工程工具的主要内容应是编辑器、数据表、字段树、HEX 网格与时间线。统计数字只辅助说明当前会话，优先展示实际可操作的工作区。

【三、统一视觉规范】
建议基础颜色：
- 应用背景 #0B0E0D。
- 面板背景 #151A17，浮层背景 #1C231F。
- 输入背景 #101512，悬停背景 #222B25。
- 主文字 #E8ECE9，次文字 #A6B2A9。
- 品牌与主操作绿色 #4DBF5C，使用现有绿色芯片品牌图标。
- 警告 #D7AF65，错误 #D77770。
- 分隔线使用低透明度的灰绿色。
允许在上述颜色附近做小幅调整，整套页面的层次与语义保持一致。
面板圆角 12–16px，输入与按钮圆角 6–8px，胶囊只用于标签或分段选择。
间距基于 4px 倍数，常用 8 / 12 / 16 / 24px。
面板通过背景层次与细边界区分；局部弹层可有轻微背景模糊。代码、HEX、表格区域使用稳定、清楚的底色。
主要中文文字 13–14px；编辑器与 HEX 使用清楚的等宽字体，12–14px；次标签不小于 12px；页面标题 20–24px。标题可以轻盈，长文本和关键数值保持足够字重。
采用统一线条图标风格；图标按钮要有工具提示与可见焦点。
连接、接收、发送、错误等状态同时使用图形和文字说明。
动效仅用于短时的悬停、展开与选择反馈。通信数据更新时保持布局稳定。
深色为完整主方案；浅色使用同一结构和组件规范，提供协议工作区与通信工作台两个对应样例。

【四、全局布局与信息架构】
主画板 1600×1000。另说明 1280×800 和 1920×1080 下的面板调整规则。
应用顶部为完整自定义标题栏，高度约 40–44px：左侧为品牌图标与 IoT Protocol Studio，中间为当前上下文和后退 / 前进，右侧为设置、最小化、最大化 / 还原与关闭。
左侧使用约 60–68px 的主导航栏，主入口只有：
1. 协议工作区
2. 调试
3. 通信
4. 环境与变量
5. 设置
协议工作区左侧增加可调整宽度的项目目录栏，默认约 240–280px；中央为主内容，可按需显示约 280–320px 的字段属性或记录详情区。
协议工作区内部有“代码 / 结构 / 报文”三个视图，属于同一份协议上下文。
通信工作区以会话标签组织 TCP、串口与 UDP；记录、关联、时间线和回放属于当前会话内部视图。
明确区分全局页面、协议内部视图、通信会话标签和记录详情，避免嵌套后无法判断当前所在位置。
工具栏常用动作直接可见，少用动作通过对象行内“更多”菜单提供。长表格与编辑区承担主要面积。
项目目录在需要项目上下文的页面出现；独立调试与通信可在未打开项目时使用。环境变量编辑需要项目。

【五、当前功能范围】
A. 项目：新建、打开、最近项目、关闭 / 移除；真实多级目录树；创建、重命名、移动、排序和删除空文件夹；创建协议；协议显示名称修改与单项删除；侧栏调宽。项目与协议的显示名称和磁盘路径要区分。
B. 协议设计：YAML 代码编辑、校验、保存、未保存状态；结构化编辑消息与字段；字段名称、显示名称、类型、字节序、偏移、长度；枚举、位域、嵌套结构、条件字段、动态数组；消息识别、长度字段和 CRC / 校验定义。
C. 报文工作台：根据已保存协议选择消息并填写字段；枚举选择、位状态、嵌套字段和数组输入；自动生成长度、消息类型及校验；保存 / 加载 / 覆盖 / 删除模板；预览 HEX、ASCII 和字节数；复制、送入调试或送入通信；字段级错误。
D. 独立调试：HEX 输入与格式化；字节序号、偏移、HEX、ASCII、十进制对照；选择字节、颜色标注、导入导出标注；协议解析与字段 / 字节双向定位；查找替换；进制、数值、字节序、BCD、时间戳、位运算和校验计算工具。
E. 通信：多会话、新建 / 重命名 / 关闭标签；分离为独立系统窗口并合并；TCP 客户端与服务端、服务端客户端列表、自动重连；Windows 串口参数；UDP 单播、广播和 IPv4 组播；协议绑定、固定 / 长度字段 / 分隔符分帧；HEX / UTF-8 发送；变量引用、动态生成值、定时与批量发送；状态、队列和错误反馈。
F. 收发分析：原始 TX / RX、完整 FRAME 与系统事件；时间、连接、设备、协议、消息、方向筛选与文本搜索；字段详情和校验结果；请求 / 响应关联、耗时、超时、重复、迟到、无匹配、歧义与无法分析；时间线；记录保存 / 导入；离线与实际发送回放；经典 PCAP 导入和诊断。
G. 环境与变量：创建、重命名、删除、切换环境；变量名称、文本 / 数字 / 布尔类型、默认值与必填；敏感值默认隐藏并可显式查看；生效环境标识；{{name}} 引用；random、sequence、timestamp 的使用提示。
H. 设置：深色 / 浅色、中文 / English；问题列表、上下文跳转；诊断日志筛选、清空与导出。
后续规划的设备模拟界面、测试中心、压力测试、脚本、AI 助手、MQTT、WebSocket、BLE、软件更新、代码生成、项目交换与协议版本管理，不进入本次首版可操作导航或功能展示。

【六、生成独立页面画板】
P01 项目入口：未打开项目状态；新建项目、打开项目、最近项目列表；进入项目后的目录树，以及文件夹 / 协议的行内操作。
P02 协议结构：项目树 + 消息 / 字段树 + 字段属性；选中字段的类型、字节序、偏移和长度；补充枚举、位域、嵌套结构、条件字段和动态数组的编辑状态。
P03 协议代码：同一项目上下文，YAML 编辑器、行号、保存状态；显示一个可定位的校验错误及对应错误行。结构 / 代码 / 报文标签一致。
P04 报文工作台：消息选择、模板选择、结构化字段表单、派生字段只读状态；下方 HEX / ASCII 预览和复制 / 送入调试 / 送入通信动作。
P05 报文调试：主 HEX 输入与字节网格；右侧解析字段；至少显示一处字段与字节联动高亮、范围标注及校验状态。
P06 调试工具：使用同一调试页面与工具面板，展示数据转换、查找替换、CRC 计算的不同状态；完整列出 BCD、时间戳和位运算的工具入口。
P07 TCP 客户端：会话标签、连接配置、连接状态、协议 / 分帧配置、实时记录、发送区；展示自动重连设置与定时 / 批量发送的展开状态。
P08 TCP 服务端：继承同一通信组件；本地监听参数、客户端列表、当前发送目标；展示选定客户端与断开操作。
P09 串口：继承同一通信组件；COM、波特率、数据位、校验位、停止位、流控；展示端口占用或断开错误反馈。
P10 UDP：继承同一通信组件；本地地址 / 端口、目标地址 / 端口；单播 / 广播 / 组播选择、网卡与加入 / 退出组播状态。
P11 关联与时间线：当前会话中配置请求 / 响应消息、关联字段、方向、范围和超时；显示匹配表和时间线；选中响应后同时看到关联请求、耗时及报文详情。
P12 历史 / PCAP 与回放：醒目的历史来源与只读标识；PCAP 导入时填写捕获端本机 IPv4；导入诊断；离线时间进度和速度；实际发送回放显示明确目标、TX / RX 与原始块 / 完整帧选择。
P13 环境与变量：环境列表、生效标识、变量表；变量名称、类型、默认值、必填和敏感属性；显式查看敏感值与变量校验错误。
P14 设置与诊断：主题、语言；问题列表与相关协议 / 会话信息；诊断日志、筛选、清空和导出。
P15 独立通信窗口：复用 P07–P10 的组件，主示例 1100×760；独立标题栏、会话名、合并回主窗口动作，保留完整收发和解析操作。

每个编号是同一产品中的独立画板或状态，不要求把所有控件同时塞进一屏。参数、发送方式和工具可通过稳定的折叠区或抽屉渐进展开。

【七、关键交互与状态】
额外提供统一组件与状态画板：
- 按钮、输入、下拉、分段选择、复选框、开关、标签、表格、树、工具提示、弹窗、抽屉、横向分隔拖动条。
- 默认、悬停、焦点、选中、禁用、加载、成功、警告和错误。
- 未打开项目、未选择协议、无记录、筛选无结果、连接中、连接失败、断线重试、未保存修改、编码失败、坏文件导入失败。
- 新建项目 / 协议、字段编辑、模板覆盖、删除协议、关闭有内容会话的确认弹窗。
错误提示必须给出原因与下一步，必要时定位字段、代码行或关联会话；导入失败保留原内容。
未保存协议时阻止依赖已保存定义的编码 / 解析操作，说明“先保存协议修改”。
导入历史和离线回放不建立连接或发包。实际发送回放要求用户明确选择已连接目标，目标初始为空。
停止发送任务后应表达“停止后续发送”；不能暗示已经发送或入队的数据被撤回。
记录有容量上限，应能看到淘汰数量。PCAP 支持范围与不支持格式放在导入上下文，不占用主工作区。
敏感变量默认隐藏；相邻文案说明默认值文件仍为明文存储，显示隐藏不等于加密。
页面和窗口布局在重启后自动恢复尚未实现，设计中不展示已经支持此功能。

【八、样例内容与一致性】
全套使用同一个“Smart Sensor Demo”项目，同一份“SensorLink”示例协议与同一组消息、字段和会话。
可使用消息名 ReadStatus / StatusReply，字段名 sequence、deviceId、temperature、flags、payloadLength、payload、crc；选择当前类型规则支持的组合。
会话命名：Sensor TCP、Device Server、Serial COM3、UDP Discovery。示例环境：Development、Lab。
示例数据均为设计演示；各页面的消息、字段顺序、类型、偏移、字节数、HEX 和校验状态相互一致。
代码和协议内容允许复制阅读；HEX 使用完整、规整的等宽字节，不将乱码或装饰线条当作报文。
每张画板使用完全相同的色值、字体、组件尺寸、导航顺序、图标、选中态和标题栏。
工程界面中不添加与当前任务无关的收入、增长、车队、乘客、地图或 AI 指标。

【九、输出要求】
先输出：
1. 一页设计系统：颜色、字体、间距、圆角、组件和状态。
2. P02 协议结构和 P07 TCP 客户端两张关键画板，用于确定风格。
方向确认后，复用规范补齐 P01–P15，包含关键弹窗与错误状态；画板使用 P01、P02 等编号命名。
最后输出组件复用关系、面板调宽规则、交互连接与开发交付说明。
如果工具能生成可编辑 UI，请创建复用组件、变量与独立页面；如果只能生成图片，每次生成一张完整页面，沿用前一批已确定的规范。
整套设计覆盖已实现功能，保留必要操作路径。对密集参数进行分组和渐进展开，确保关键动作始终容易找到。
```
