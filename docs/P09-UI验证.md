# P09 串口界面验证

日期：2026-10-04

final result: passed

## 实现范围

基于用户提供的四组 P09 UI 图片修改现有串口模式。保留产品已经确认的芯片品牌、圆角导航、Bug / Radio 图标和深浅主题，沿用 TcpWorkspace、TcpWorkbench、原生串口 transport / Core 与已有发送逻辑。

- 顶部：端口、波特率、数据位、校验位、停止位、流控、刷新、连接状态与打开 / 关闭 / 重试；右侧协议绑定和分帧参数。
- 主区：方向筛选、消息 / HEX 搜索、解析状态、暂停显示、收发计数、收发记录 / 时间线 / 统计，以及已有分析 / 回放入口。
- 详情：报文摘要、HEX / ASCII、字段解析、校验；字段选择高亮真实字段范围对应的字节。
- 发送：HEX / UTF-8、字节数、Ctrl+Enter、清空、发送后自动清空及已有定时 / 批量 / 变量入口。
- 三种状态：已打开正常收发；占用 / 权限错误和重试；通信中断、保留记录与所选详情、发送禁用和重新打开。

## 对照与修正

主参考使用图片 4 的 P09-A，结合图片 1–3 的字段详情与三种状态。按 1586 × 634 对照参考与实现，同时核对 1600 × 1000 完整工作台。

1. 矮窗口首次检查发现发送按钮被裁切，改为紧凑发送行，格式切换放在发送页签右侧。
2. 顶部配置与高级工具占用过多记录空间，压缩配置标题行，将高级筛选入口移到记录标题行，保留所有既有文件 / 过滤功能。
3. 800px 宽时网格行被压缩而发生区块重叠，改为纵向 flex 和分区最小高度；修复后连接、协议、记录、发送、详情依次排列，可滚动访问。
4. 最终同图对照检查布局、间距、颜色、图标、文字和状态；无剩余 P0 / P1 / P2 缺陷。

与图片的明确差异：会话来自实际状态，不新增图片中的虚构连接；保留现有分析、回放、PCAP、变量和生效值检查入口。字段列及校验状态只显示 Core 已返回的信息，不硬编码算法、CRC 计算值或参考报文。634px 矮窗口中表格和详情内部滚动。

## 浏览器交互证据

预览挂载实际产品组件，只有 test/serial-fixture.js 提供模拟 bridge 数据，不进入生产入口。

| 检查 | 实际结果 |
| --- | --- |
| 打开串口 | COM3 / 115200 / 8-N-1，显示绿色打开状态，参数锁定，发送可用 |
| TX / RX / 搜索 | 示例数据分别匹配 4 个 TX、4 个接收完整帧；StatusReply 搜索匹配 4 条 |
| 字段联动 | temperature 选中后高亮偏移 11–14 的四个字节 |
| 暂停 / 恢复 | 暂停时显示 9 条；期间快捷发送，恢复后显示 10 条，底层收取继续 |
| 自动清空 | 成功发送后发送输入清空 |
| UTF-8 | “你好”显示 6 bytes，TX 显示 e4 bd a0 e5 a5 bd |
| 统计 | 分别统计 TX、RX、FRAME、SYS；FRAME 不重复累计到原始 RX 字节 |
| 占用 | native 样式错误码 5，显示占用 / 拒绝访问提示、无记录空状态、发送禁用；释放模拟占用后重试成功 |
| 中断 | 11 条记录保留并追加 1 条 SYS；所选详情保留；发送禁用；重新打开后可发送 |
| 分帧 | 展开并应用长度字段偏移、宽度、附加长度和字节序参数，折叠入口正常 |
| 其他发送入口 | 定时 / 批量参数可见，定时发送入口执行；保留既有变量语法与排队行为 |
| 主题 / 尺寸 | 深色 1586 × 634、1600 × 1000；浅色英文 1000 × 720；800 × 700 纵向滚动；文档无横向溢出 |
| 控制台 | 当前验证页 error 列表为空 |
