- 用户提供的四张 P10 图片均包含单播、广播和 IPv4 组播状态。采用共通的布局：上方 UDP 配置和协议配置，左侧收发记录及发送区，右侧贯穿主体的报文详情。

- 使用既有 UDP Core / Bridge；每个 UDP 数据报独立解码，协议区显示“完整 UDP 数据报”，不复用 TCP 字节流长度分帧。

- `UdpConnection.tsx`：单播 / 广播 / IPv4 组播切换、本地与目标地址 / 端口、网卡刷新、组播网卡、加入 / 退出和实际状态。

- `TcpWorkbench.tsx`：以上组件接入现有会话、收发、筛选、统计、定时 / 批量、变量与快捷发送流程；其他并行任务的变更继续保留。

## 数据与验收边界

- 接收来源来自 Core 的真实远端地址；本地端点来自捕获时的会话绑定快照。通配绑定地址不等同实际来源或目标 IP，详情提供说明；历史导入没有本地端点元数据时显示 `—`。
- 校验只呈现 Core 返回的通过 / 失败 / 未执行状态。算法、计算值和报文值尚无独立元数据，不硬编码 CRC16-Modbus。
- 继续使用既有记录保存 / 导入 / 导出、时间线、关联及回放入口。没有为参考图中的无限循环、每次发送自动追加历史等功能建立平行实现。
- 浏览器 fixture 的报文及解析结果用于 UI 验证，不能证明真实协议 Codec、设备、跨主机或组播路由行为。真实跨主机 UDP 和原生文件选择器人工验收继续保留。
