## 记录与更新规则

- 此文件作为后续功能进度更新入口；完成或调整功能时，同步更新对应条目的状态、时间和必要说明。
- 其他既有功能设计及进度文件暂时保持不动；本清单以原设计方案为范围，结合当前实现整理。
- 状态：✅ 已完成；🟡 部分完成；⬜ 未完成。模块下仍有未完成项时，模块不能标记为已完成。
- 记录时间表示条目首次纳入本清单的日期，本次统一为 2026-09-05；后续新增条目填写实际记录日期。
- 完成时间表示本条所述用户交互范围实现完成的日期。已有功能根据对应 Git 实现提交日期回填，不表示本次重新完成了人工验收；无法追溯的日期填写“待核实”，不推测。
- 未完成或部分完成的条目，完成时间填写“—”；模块全部完成后，再填写模块完成时间。
- 后续更新保留原记录时间；实际完成并验证后填写完成时间。范围扩大或状态回退时，调整状态并在更新记录中说明。
- 仅有底层接口、算法、测试骨架或界面占位，不算用户交互功能已完成。
- 日期使用 YYYY-MM-DD。每次进度变化同时更新文件顶部的最近更新时间，并追加一条简短更新记录。

## 当前进度

已实现项目与文件夹管理、协议创建和代码编辑、消息与基础字段的可视化增删改及字段排序、基础表单组包。调试页支持标注文件导入导出、查找替换、数据转换、校验计算，以及按已保存协议解析基础字段和双向定位。TCP 客户端 / 服务端支持收发、记录保存、接收分帧与会话级协议 / 消息绑定；完整帧可自动识别消息并保存字段解析、范围及校验结果，从记录进入调试可继续双向定位。

整数枚举已接入结构编辑、协议保存、组包选择、调试与完整帧记录：显示名称和原始数值，未知数值仍按原始整数保留。

位域、嵌套结构、条件字段和动态数组已接入可视化编辑及 Core 编解码。组包表单随前置字段值更新，调试展示完整字段路径与实际字节范围；长度字段和 CRC 随动态布局重算。

页面切换或仅格式化输入会保留结果和标注，报文内容改变或重新解析会清除旧标注。跨应用重启保留标注可通过导出、再导入 `.iotdebug.json` 文件完成；文件同时包含原报文，导入失败保留当前数据，不自动恢复上次会话。

## 调试模块的前置条件与边界

| 功能 | 依赖模块 / 前置条件 | 当前状态 |
|---|---|---|
| 基础协议解析、字段与 HEX 双向定位 | 项目模块：打开项目；协议设计：保存协议与消息定义，先保存未提交的代码修改；编解码：返回字段值和范围 | 前置能力已具备，本次已接通；不需要通信连接 |
| 位域、嵌套结构、条件字段、动态数组解析 | 协议设计：相应类型和动态布局定义；编解码：相应解析规则及字节范围 | 枚举已完成；其余前置能力未完成，保留为待办，不在调试页模拟实现 |
| 自动识别消息类型 | 协议设计：定义报文内识别字段及匹配规则；编解码：自动消息匹配 | 完整 FRAME 可按会话绑定的协议识别并标记消息；独立调试仍手动选择 |
| 实时接收后自动解析、请求 / 响应和时间线 | 通信连接、收发记录与分析模块 | TCP 完整帧可解析字段和校验；请求 / 响应关联及时间线仍待阶段 6 |

独立调试工具不依赖项目或连接，数值计算与协议解析在 Windows 桌面端执行。转换、位运算、查找替换和校验工具单次最多处理 64 KiB；标注文件最多 1 MiB、1000 条标注，每条说明最多 160 字符。校验范围采用从 0 开始的偏移，起止均包含；普通 SUM / XOR / LRC 不需要 CRC 参数。BCD 使用偶数位十进制数字，保留前导零；时间戳使用 64 位有符号 Unix 秒 / 毫秒及 UTC 日期（0001–9999 年），支持选择字节序。移位按首字节为高位的整段报文计算，补零并保持长度。

### 阶段 6：收发分析、时间线与回放

目标：从“看见字节”推进到“解释一次通信为什么成功或失败”。

- [ ] 6.1 **结构化筛选补齐**〔收发记录与分析，补齐剩余部分〕：连接 / 会话、设备、消息类型、时间区间；设备标识来自配置或已解析字段，不增加设备资产管理模块。保留已有方向和文本筛选。
- [ ] 6.2 **请求 / 响应关联**〔收发记录与分析〕：配置关联字段、连接范围及超时；区分正常响应、超时、重复和无匹配响应，不能只靠“下一条 RX”判断。
- [ ] 6.3 **消息时间线**〔收发记录与分析〕：展示请求、响应、异常及耗时；可跳到原始报文和解析结果。
- [ ] 6.4 **数据回放与速度控制**〔收发记录与分析〕：先离线按时间顺序回放已保存会话，再提供明确选择目标连接的发送回放；区分只看记录与实际发包，支持暂停 / 停止。
- [ ] 6.5 **PCAP 导入与分析**〔收发记录与分析〕：先明确支持的链路和网络协议范围，提取 UDP 报文、重组 TCP 字节流，再复用分帧和解析；截断、缺包和不支持的数据应显式报告。

**验收条件：** 能从一次保存的通信定位超时原因、复现报文顺序，并说明哪些数据无法可靠解析；导入与离线回放不会意外向设备发包。

### 阶段 7：项目复制、交换、归档与基础文档

目标：让已有协议和调试成果能够交付给另一台电脑或另一个使用者。

- [ ] 7.1 **协议文件改名**〔协议设计，拆分原组合条目〕：区分文件路径与显示名称；同步项目引用、报文模板及其他已建立的关联；失败时回滚，避免出现孤立模板。
- [ ] 7.2 **项目复制**〔项目〕：明确新项目标识、名称和目标目录，保留协议和模板，校验冲突并保证原项目不变。
- [ ] 7.3 **项目模板**〔项目〕：与现有“报文模板”区分；支持从项目模板创建新项目并检查模板兼容性。
- [ ] 7.4 **项目导出、再实现导入**〔项目〕：确定包含的协议、模板及可共享配置，检查路径、冲突和损坏内容；导入成功进入历史项目列表，失败不替换当前项目，不携带敏感变量明文。
- [ ] 7.5 **项目归档**〔项目〕：明确归档状态、存放位置与重新打开方式，区别于“移出历史列表”和文件删除。
- [ ] 7.6 **数据备份与恢复**〔设置与通用操作，拆分原组合条目〕：明确备份范围、覆盖确认、格式兼容及失败恢复；复用项目打包与文件校验，不另做一套不兼容格式。
- [ ] 7.7 **协议字段说明、示例报文与 Markdown / HTML 文档导出**〔文档与代码生成〕：从同一份已校验 Schema 生成，示例报文经过编码与解码验证。

**验收条件：** 在另一目录或电脑导入项目后，可打开协议、加载模板、生成相同报文；项目与协议改名不会破坏引用，导出文档与实际协议一致。

**可提前分支：** 项目复制 / 导入导出与基础协议文档可按当前已支持字段提前实现；不需要为此等待所有通信协议完成，但必须明确支持范围。

### 阶段 8：自动化测试中心

目标：把已验证的人工流程转为可重复、可判定的测试。

- [ ] 8.1 **创建测试用例与测试套件**〔测试中心〕：保存步骤、输入及预期结果，关联协议与环境。
- [ ] 8.2 **连接、发送、接收、断言步骤**〔测试中心〕：明确超时、失败后继续 / 停止、连接释放；支持原始字节和已解析字段断言。
- [ ] 8.3 **先单个执行，再批量执行**〔测试中心〕：显示运行状态和逐步结果，支持取消；隔离用例数据、连接和变量。
- [ ] 8.4 **参数化、边界与异常测试**〔测试中心〕：复用变量和报文生成能力，覆盖非法输入、超时、坏校验和断线。
- [ ] 8.5 **测试结果查看与报告导出**〔测试中心〕：包含用例、步骤、实际 / 预期、错误及相关收发记录，保留可复现所需的非敏感配置。

**验收条件：** 一套正常 / 异常用例可重复运行并得到确定的通过或失败结果；取消后无遗留连接与发送任务；报告能定位失败步骤。

**边界：** 测试中心首版可用现有 TCP 服务端、真实设备或已有模拟底层验证，不必等待阶段 9 的完整设备模拟界面；也不依赖脚本或插件系统。

### 阶段 9：设备模拟，再推进压力测试

目标：先稳定模拟单个设备，再复用它做批量与负载场景。

- [ ] 9.1 **创建模拟设备并绑定协议、连接**〔设备模拟〕：明确设备实例与变量作用域，复用已有模拟 Core 能力时补齐实际交互。
- [ ] 9.2 **启动、停止和状态查看**〔设备模拟〕：显示连接和任务状态，停止时释放连接、定时任务和队列。
- [ ] 9.3 **按请求自动响应**〔设备模拟〕：基于消息识别与字段条件匹配，生成可追踪的响应。
- [ ] 9.4 **自动登录、心跳与定时上报**〔设备模拟〕：区分连接建立后的登录和持续任务，复用变量与发送调度。
- [ ] 9.5 **错包、延迟、超时、断线故障模拟**〔设备模拟〕：故障可配置、可关闭，并能被阶段 8 的测试检测到。
- [ ] 9.6 **批量设备模拟**〔设备模拟〕：每个实例有独立标识和状态，限制资源占用；控制层批量管理，不为每个模拟设备建立独立调试窗口。
- [ ] 9.7 **压力参数配置与启动 / 停止**〔压力测试〕：设备数、并发量、运行时长和负载目标；明确资源上限与取消清理。现有 16 个交互会话上限不等于压测能力，应单独验证执行器容量。
- [ ] 9.8 **指标与报告**〔压力测试〕：吞吐量、延迟、错误率及资源使用，先明确统计口径，再提供实时查看和性能报告导出。

**验收条件：** 单设备行为有自动化测试；多设备状态互不污染；压测停止后资源恢复，指标与实际完成的操作相符。

### 阶段 10：按设备需求扩展通信协议

默认放在核心调试与自动化能力稳定后；有确定目标设备时，可在阶段 1 / 4 后提前对应子项。

- [ ] 10.1 **WebSocket**〔通信连接〕：连接参数、文本 / 二进制消息边界、断开与重连，沿用会话和记录视图。
- [ ] 10.2 **MQTT**〔通信连接〕：Broker、认证、主题发布 / 订阅与消息元数据；协议报文解析针对有效载荷，不把 MQTT 包边界混同于 TCP 收到的数据块。
- [ ] 10.3 **BLE**〔通信连接〕：扫描与设备选择、服务 / 特征、读写 / 通知、断开和权限错误；需要真实适配器及设备验证。

**验收条件：** 每一种方式都有可操作的连接界面、可验证的收发、错误反馈和资源释放。按确定的支持范围逐个交付，不一次实现所有协议的全部选项。

### 阶段 11：扩展能力与产品完善

本阶段子项可独立排期，以下顺序优先交付直接减少日常操作的能力。

- [ ] 11.1 **全局搜索与命令面板**〔设置与通用操作〕：先搜索现有项目、协议、消息与可用操作，尊重当前上下文和未保存保护。
- [ ] 11.2 **快捷键配置**〔设置与通用操作〕：复用命令入口，校验冲突，在主窗口与独立窗口中正确定位当前会话。
- [ ] 11.3 **各语言协议结构与编解码代码生成**〔文档与代码生成〕：依赖稳定的 Schema / Codec；按实际需要逐语言交付，生成代码必须通过同一组协议测试向量。
- [ ] 11.4 **Wireshark 解析脚本生成**〔文档与代码生成〕：依赖稳定字段布局和消息识别；用实际捕获数据或阶段 6 的 PCAP 样本验证字段及偏移。
- [ ] 11.5 **脚本编写、保存与执行**〔脚本与扩展〕：先确定最小脚本 API、超时 / 取消和可访问资源范围，再选运行时；不要先搭建通用脚本平台。
- [ ] 11.6 **发送前 / 接收后脚本、自定义编解码与数据生成**〔脚本与扩展〕：依赖 11.5；明确执行顺序、输入输出校验、失败时是否发送及记录方式，不能绕过通信和数据校验边界。
- [ ] 11.7 **插件安装与管理**〔脚本与扩展〕：在实际扩展点稳定后实现安装、启停、卸载、兼容性和权限处理；内置功能不为插件架构提前重写。
- [ ] 11.8 **软件更新**〔设置与通用操作，拆分原组合条目〕：在有明确发布与分发方式后实现版本检查、可信包校验、安装失败处理及数据兼容；复用阶段 7 的备份恢复。

**验收条件：** 每个扩展都有实际使用入口和故障处理；生成代码 / 脚本有可运行样例；安装或更新失败不损坏项目数据。

### 阶段 12：AI 协议助手（远期）

- [ ] 12.1 **根据资料辅助生成协议定义**：输出进入现有 Schema 校验与人工确认流程，不能直接覆盖已保存协议。
- [ ] 12.2 **分析未知报文与建议字段划分**：依赖已有原始数据、解析和样本管理，区分可验证事实与推测。
- [ ] 12.3 **解释解析错误与校验问题**：基于真实字段路径、字节范围、校验结果和测试证据给出建议。

**验收条件：** AI 建议可检查、可拒绝，并能由既有校验 / 测试能力验证；AI 不是协议解析正确性的前置条件。

### 暂缓事项与范围约束

- **协议版本管理：暂缓，不纳入以上执行阶段。** 用户此前明确“先不做版本控制”；源清单“协议文件改名与版本管理”中的文件改名安排在 7.1，版本管理只有在重新明确需求后才排期。暂缓不等于已完成。
- **独立批量删除入口：不恢复。** 当前约定为对象行内“更多”与单项删除；“批量发送”“批量测试”是不同功能，不受此约束。
- **会话配置 / 草稿 / 窗口布局跨重启恢复：作为现有边界保留。** 不把它与 1.1 的“会话收发记录保存 / 导入导出”混为同一交付；需要时另立执行项。
- **不预填完成日期或虚构工期。** 本节是依赖与优先级排序，阶段工期应在开始开发、确认细分范围后估算。
