## 记录与更新规则

- 此文件作为后续功能进度更新入口；完成或调整功能时，同步更新对应条目的状态、时间和必要说明。
- 其他既有功能设计及进度文件暂时保持不动；本清单以原设计方案为范围，结合当前实现整理。
- 状态：✅ 已完成；🟡 部分完成；⬜ 未完成。模块下仍有未完成项时，模块不能标记为已完成。
- 记录时间表示条目首次纳入本清单的日期，本次统一为 2026-09-05；后续新增条目填写实际记录日期。
- 完成时间表示本条所述用户交互范围实现完成的日期。已有功能根据对应 Git 实现提交日期回填，不表示本次重新完成了人工验收；无法追溯的日期填写“待核实”，不推测。
- 未完成或部分完成的条目，完成时间填写“—”；模块全部完成后，再填写模块完成时间。
- 后续更新保留原记录时间；实际完成并验证后填写完成时间。范围扩大或状态回退时，调整状态并在更新记录中说明。
- 仅有底层接口、算法、测试骨架或界面占位，不算用户交互功能已完成。
- 日期使用 YYYY-MM-DD。每次进度变化同时更新文件顶部的最近更新时间，并追加一条简短更新记录。

## 当前进度

已实现项目与文件夹管理、协议创建和代码编辑、消息与基础字段的可视化增删改及字段排序、基础表单组包。调试页已补齐标注文件导入导出、查找替换、数据转换、校验计算，以及按已保存协议解析基础字段和双向定位。高级协议解析仍依赖协议设计能力；实际通信收发和收发记录分析尚未形成完整交互闭环。

页面切换或仅格式化输入会保留结果和标注，报文内容改变或重新解析会清除旧标注。跨应用重启保留标注可通过导出、再导入 `.iotdebug.json` 文件完成；文件同时包含原报文，导入失败保留当前数据，不自动恢复上次会话。

## 调试模块的前置条件与边界

| 功能 | 依赖模块 / 前置条件 | 当前状态 |
|---|---|---|
| 基础协议解析、字段与 HEX 双向定位 | 项目模块：打开项目；协议设计：保存协议与消息定义，先保存未提交的代码修改；编解码：返回字段值和范围 | 前置能力已具备，本次已接通；不需要通信连接 |
| 枚举、位域、嵌套结构、条件字段、动态数组解析 | 协议设计：相应类型和动态布局定义；编解码：相应解析规则及字节范围 | 前置能力未完成，保留为待办，不在调试页模拟实现 |
| 自动识别消息类型 | 协议设计：定义报文内识别字段及匹配规则；编解码：自动消息匹配 | 前置能力未完成，当前手动选择消息 |
| 实时接收后自动解析、请求 / 响应和时间线 | 通信连接、收发记录与分析模块 | 尚未完成，仍归属相应模块；当前调试处理手动输入报文 |

独立调试工具不依赖项目或连接，数值计算与协议解析在 Windows 桌面端执行。转换、位运算、查找替换和校验工具单次最多处理 64 KiB；标注文件最多 1 MiB、1000 条标注，每条说明最多 160 字符。校验范围采用从 0 开始的偏移，起止均包含；普通 SUM / XOR / LRC 不需要 CRC 参数。BCD 使用偶数位十进制数字，保留前导零；时间戳使用 64 位有符号 Unix 秒 / 毫秒及 UTC 日期（0001–9999 年），支持选择字节序。移位按首字节为高位的整段报文计算，补零并保持长度。
